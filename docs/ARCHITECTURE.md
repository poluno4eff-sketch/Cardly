# Архитектура Cardly

## 1. Главный принцип

Cardly — открытый проект под GPL-3.0 (см. `NOTICE.md`). Экран оплаты на часах основан на Mir Pay Wallet (the-dise, GPL-3.0); Catima — референс функций. Заимствования указываются в `NOTICE.md`.

## 2. Offline-first

Телефон и часы должны иметь собственную локальную копию данных. Отсутствие Интернета или временная потеря связи телефон ↔ часы не должна мешать открытию уже синхронизированных карт.

На следующих этапах локальная база будет реализована через Room. Настройки — через DataStore.

## 3. Синхронизация Wear OS

Основной механизм — официальный Wear OS Data Layer:

- `DataClient` / `DataItem` для состояния карт и метаданных;
- `Asset` для изображений карт;
- `MessageClient` только для коротких команд и запросов, которым нужна немедленная реакция;
- локальная база на каждом устройстве остаётся источником данных для UI.

На первом этапе редактирование карт выполняется на телефоне, часы являются быстрым клиентом просмотра. Избранное и порядок на часах добавим после стабилизации основной синхронизации.

## 4. План модулей

### mobile

Главный экран, добавление/редактирование карт, сканер, поиск, группы, сортировка, архив, импорт/экспорт, настройки.

### wear

Три экрана свайпом: скидочные карты ← оплата (открывается при запуске) → настройки оплаты. Экран оплаты держит экран включённым по таймеру, пока Mir Pay проводит оплату; есть компликация и опциональная служба спецвозможностей, которая открывает Cardly вместо Google Wallet. Список синхронизированных карт, избранное, открытие штрихкода, максимальная яркость, быстрый переход между соседними картами.

### core:model

Единые модели `Card`, `Barcode`, `CardImage`, `Group`, `SyncRevision`.

### core:data

Room, DAO, репозитории, миграции базы, работа с изображениями и резервными копиями.

### core:barcode

Распознавание камерой/изображением и генерация 1D/2D-кодов.

### core:sync

Сериализация, Wear Data Layer, конфликты версий, очередь изменений и диагностика синхронизации.

## 6. Конфликты

Каждое изменение получает `updatedAt` и монотонную `revision`. Для первой версии телефон является устройством редактирования и публикует актуальное состояние на часы. После появления редактирования на часах будет добавлено разрешение конфликтов по revision + времени изменения.

## 7. Безопасность и приватность

- без обязательной регистрации;
- без рекламных SDK и скрытой аналитики;
- локальная работа без сети;
- облачная резервная копия только как отдельная опция пользователя;
- минимальный набор Android-разрешений;
- резервные копии не должны включать лишние системные данные.

## 8. UI

Главный экран (0.3.0): AMOLED-чёрный фон, логотип Cardly (шрифт Pirata One, градиент как у кнопки «+»), сверху кнопки: поиск, вид, сортировка, «+», меню. Три крупные карты на экране (высота плитки считается от экрана). Внизу — компактный переключатель «Карты / Визитки»; приложение всегда открывается на картах и возвращается к ним после минуты в фоне.

Визитки хранятся только на телефоне (таблица `business_cards`, Room v3), на часы не передаются. Распознавание — офлайн: QR vCard/MeCard, затем Tesseract (rus+eng) и разбор полей (`BusinessCardParser`).

Карты должны быть визуальным центром приложения.
